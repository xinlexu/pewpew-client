# Discord 线路检测

本功能包含在 0.1.5 Windows 内测包中。Windows 隔离测试不等于真实安装、TUN、Discord 直播或 macOS 验证。

## 用户行为

- 不新增独立设置入口。增强兼容开启、智能分流模式、Discord 桌面进程运行时才有资格短测；全局与直连模式保持原行为。
- 连接过程不等待短测。后台比较当前线路和最多两条候选，用 UDP 回执估计丢包、往返延迟、抖动和有限上传承载能力。
- 当前线路达到保守门槛时不切换。候选必须达到门槛、明显改善并通过第二次确认，才用于 Discord 的新连接。正在进行的连接不强制断开。
- 主界面或托盘手动选线会取消后台结果，Discord 恢复原有分流；本次连接不再自动择优。断开增强兼容后可重新启用自动判断。
- “检查连接”显示跟随当前分流、短测中、短测择优或手动选择，不把失败或缺少证据说成优化成功。
- 已知其他代理软件运行时，连接前建议从系统托盘或菜单栏退出，允许取消或仍然连接。不自动结束其他软件。

## 范围与限制

检测目的地是现有 DigitalOcean SFO2 服务器 `138.68.16.189`，不是 Discord 的语音服务器。到它的结果不能保证所有 Discord 区域同样表现良好，更不能承诺直播提速。暂不支持识别浏览器中的 Discord 标签页。

只增加 Discord 域名和桌面进程 UDP 规则，以及检测服务器两个端口的规则。选择器默认 PASS，未选定时继续原有规则。选择后 Discord 规则优先于订阅规则；有严格自定义 Discord 路由需求时应手动选择线路。局域网、回环、链路本地和组播目的地不经进程规则调整。

每次连接最多进行一轮，且两轮之间至少 30 分钟。每个候选发送 1,500 个 1,000 字节 UDP 数据包，最多四次测量（当前、两条候选、一次确认），约 6 MB 应用载荷，加上协议开销。不会跑无限速上传或上传用户文件。网络接口地址变化会作废旧结果；同一地址下的 Wi-Fi 网络切换不一定可被识别，可重新连接重新评估。

不可用、忙碌、认证失败、证据不足、UDP 不通、候选不够、代理需要未配置的本地认证时均保守跟随原分流。短测门槛是启发式规则，不是 Discord 官方质量标准。

## 服务与安全

源码位于 `services/route-probe`，Python 标准库实现。与音乐机器人独立运行，不共享机器人目录、配置或凭据。

- `18443/TCP`：TLS 会话签发、结束、健康检查。客户端验证仓库内公开证书，不关闭 TLS 校验。
- `18444/UDP`：仅接受随机 24 字节、12 秒有效会话令牌。每个 1,000 字节请求最多返回一次 32 字节回执，绑定首次 UDP 来源地址，不转发流量。
- 同时最多一个检测会话；每分钟最多 12 次、每天最多 256 次，日配额持久化。每会话最多 2,200 包，最多每秒 1,000 包。
- systemd 动态用户、只读系统、64 MB 内存、20% CPU、16 个任务、64 个文件句柄上限。HTTP 头大小和等待时间有界。
- 不记录客户端 IP、令牌、线路名或业务内容。服务端只存配额计数；系统和供应商仍可能保留网络运行记录。
- 端点是公开的，不具有付费账户鉴权。恶意占用可以耗尽检测配额，此时客户端回退，不能据此声称具备抗 DDoS 能力。

TLS 私钥仅在服务器 `/etc/pewpew-probe/server.key`，通过 systemd credential 传给服务；仓库只提交公开证书。证书有效期两年，换密钥/证书前需要客户端同步信任新证书。不要把 TLS 私钥或客户端更新签名私钥提交 Git。

## 部署与回退

第一次部署：仅上传 `services/route-probe`，在服务器的独立暂存目录执行 `sh deploy.sh`。脚本拒绝覆盖已存在的部署。版本目录 `/opt/pewpew-probe/releases/20261028`，运行链接 `/opt/pewpew-probe/current`，配置 `/etc/pewpew-probe`，配额 `/var/lib/pewpew-probe`。

查看：`systemctl status pewpew-probe`、`journalctl -u pewpew-probe`。

停用回退（不影响音乐机器人）：

```sh
systemctl disable --now pewpew-probe
ufw delete allow 18443/tcp
ufw delete allow 18444/udp
```

保留原文件和证书以便恢复。客户端检测失败时继续原分流，不需要回滚内核。不要关闭整个防火墙或重启音乐机器人。
